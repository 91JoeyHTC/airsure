# AirCare v2 分群與評分機制

版本：AirCare v2 / 2026-08-04  
整理日期：2026-09-03

## 1. 適用前提與資料有效性

- 正式分析預設採用所有設備相同的 90 個台北日曆日窗口。
- 窗口迄日為最新完整感測日；起日為迄日前 89 天；時區為 `Asia/Taipei`。
- 正式分群、Aircare 指數與使用狀態結論，均須同時符合：
  - 感測有效日數 >= `ceil(窗口天數 × 70%)`
  - 狀態有效日數 >= `ceil(窗口天數 × 70%)`
- 90 天窗口的門檻為感測與狀態各至少 63 天。
- 若使用者明確指定其他窗口，門檻隨窗口天數重新計算；不同窗口的設備不應直接做相對比較。
- 有效感測日：窗口中具有有效 PM2.5 與濕度資料的不同日期數。
- 有效狀態日：窗口中具有可判斷設備狀態資料的不同日期數。
- 累積分析日：同一天同時有感測與狀態資料的日期數，且必須滿足「累積分析日 <= 資料起訖日數 <= 分析窗口天數」。

資料不足時，僅揭露資料覆蓋狀態與可驗證事實，不輸出正式分數、分群或使用狀態結論。

## 2. 核心原則：分群與評分分離

- **分群**：以分析期間平均 PM2.5 與平均濕度，依 P×H 決策矩陣決定客戶分群與建議方向。
- **評分**：以相同兩個平均值，分別計算 PM2.5 分數與濕度分數，再組成 Aircare 指數。
- 分群用的濕度區間與濕度分數函數是兩套不同規則；不得由分數反推分群。
- 耗材、濾網、水箱與人為操作不再合併為整機健康總分，僅以可驗證的維護或使用事實呈現。

## 3. 分群機制

### 3.1 輸入與優先順序

1. PM2.5 輸入下限夾為 0；濕度輸入夾在 0-100%。
2. 若濕度 <= 45%，優先分類為「乾燥（HH）」，不再以 PM2.5 決定分群。
3. 其他情況先取得 PM2.5 等級 P1-P4 與濕度等級 H1-H4。
4. 以完整 P×H 矩陣產生唯一分群結果。

### 3.2 PM2.5 分群等級

| 等級 | 期間平均 PM2.5（μg/m³） |
|---|---:|
| P1 | 0-5 |
| P2 | >5-12 |
| P3 | >12-30 |
| P4 | >30 |

### 3.3 濕度分群等級

| 等級 | 期間平均濕度 |
|---|---:|
| HH | <=45%（優先覆蓋） |
| H1 | >45%-60% |
| H2 | >60%-65% |
| H3 | >65%-75% |
| H4 | >75% |

### 3.4 P×H 分群矩陣

| 濕度等級 \ PM2.5 等級 | P1 | P2 | P3 | P4 |
|---|---|---|---|---|
| H1 | 金級空氣 | 銀級空氣 | 清淨風險 | 清淨風險 |
| H2 | 銀級空氣 | 銅級空氣 | 清淨風險 | 清淨風險 |
| H3 | 濕度風險 | 濕度風險 | 清淨除濕雙風險 | 清淨除濕雙風險 |
| H4 | 濕度風險 | 濕度風險 | 清淨除濕雙風險 | 清淨除濕雙風險 |
| HH | 乾燥，不論 PM2.5 等級 | 乾燥，不論 PM2.5 等級 | 乾燥，不論 PM2.5 等級 | 乾燥，不論 PM2.5 等級 |

### 3.5 正式報告揭露政策

| 分群 | 建議軸 | 正式客戶報告是否直接揭露 |
|---|---|---|
| 金級空氣 | 維持 | 是 |
| 銀級空氣 | 維持 | 是 |
| 銅級空氣 | 維持 | 否 |
| 清淨風險 | PM2.5 | 否 |
| 濕度風險 | 濕度 | 否 |
| 清淨除濕雙風險 | PM2.5 + 濕度 | 否 |
| 乾燥 | 乾燥 | 否 |

未直接揭露的分群僅作內部建議方向；報告應以測得事實與建議敘述呈現，不直接對客戶顯示其內部分群名稱。

## 4. Aircare 指數評分

Aircare 指數滿分 100 分：

```text
Aircare 指數 = PM2.5 分數 × 0.5 + 濕度分數 × 0.5
```

兩個組成分數皆以分析期間平均值計算，輸入小數不得預先四捨五入。

### 4.1 PM2.5 分數

PM2.5 分數為 0-100 的連續分段線性函數，越低越好。

| PM2.5 x（μg/m³） | 分數公式 | 端點分數 |
|---|---|---:|
| 0 <= x <= 5 | `100 - 2x` | 100 至 90 |
| 5 < x <= 12 | `90 - 3(x - 5)` | 90 至 69 |
| 12 < x <= 15 | `69 - 3(x - 12)` | 69 至 60 |
| 15 < x <= 30 | `60 - 4(x - 15)` | 60 至 0 |
| x > 30 | `0` | 0 |

報告用 PM2.5 等級與分數函數不同，但共用相同工作簿的級距：極淨 0-5、優良 6-12、尚可 13-15、待改善 16-29、不健康 >=30。

### 4.2 濕度分數

濕度分數為 0-100 的連續分段線性函數。濕度先夾在 0-100%。

| 濕度 h | 分數公式 |
|---|---|
| h <= 35% | `60` |
| 35% < h <= 40% | `60 + (h - 35) × 4` |
| 40% < h <= 45% | `80 + (h - 40) × 4` |
| 45% < h <= 60% | `100` |
| 60% < h <= 65% | `100 - (h - 60) × 6` |
| 65% < h <= 70% | `70 - (h - 65) × 3` |
| 70% < h <= 75% | `55 - (h - 70) × 2` |
| 75% < h <= 100% | `max(0, 45 - (h - 75) × 1.8)` |

重要錨點：35%=60 分、40%=80 分、45-60%=100 分、65%=70 分、70%=55 分、75%=45 分、80%=36 分、100%=0 分。

## 5. 使用行為分類

使用行為 `power_behavior` 與空氣分群 `aircare_segment` 完全獨立。計算時區為 `Asia/Taipei`。

| 代碼 | 標籤 | 條件 |
|---|---|---|
| A | 全天候運作 | 活躍日比例 >=90%，且平均每日開機 >=20 小時 |
| B | 固定時段使用 | 活躍日比例 >=70%，且平均每日開機 <20 小時 |
| C | 半數使用 | 活躍日比例 >=40% 且 <70% |
| D | 極少使用 | 活躍日比例 <40% |

對 B 類，若任一時段開機比例 >50%，會附加時段代碼：`M` 早上（06:00-12:00）、`A` 下午（12:00-18:00）、`E` 晚上（18:00-24:00）、`N` 深夜（00:00-06:00）。例如 `B-EN` 表示固定於晚上與深夜使用。

## 6. 相對排名的適用範圍

- 正式報告可使用的 percentile facts 僅限 `pm25_daily_avg` 與 `aircare_index`。
- 相對比較必須使用相同分析窗口與同一比較母體。
- PM2.5 為越低越好；Aircare 指數為越高越好。
- 無效資料、資料完整性、耗材、水箱與操作事實不得被包裝為正式相對排名或空氣分數。

## 7. Runtime 權威來源

實際生效的公式由 PostgreSQL `scoring_config` 表中 `active = TRUE` 的設定決定；程式在執行時讀取，不以硬編碼公式為準。

本次核對的 active 設定版本：

| 欄位 | 版本 |
|---|---:|
| `air_quality_index`（PM2.5 分數） | 9 |
| `environmental_humidity_index`（濕度分數） | 7 |
| `aircare_index` | 2 |
| `environmental_quality_index`（相容別名） | 3 |
| `power_behavior` | 3 |
