AirCare × 數據中台　架構關係圖

中台＝對內工廠（算＋產）｜ AirCare 網頁＝對外出貨口（免登入、每客戶／每設備一份）
核心原則：中台內部即時 query／不預存　·　但對外 AirCare 報告一律採「快照」——安全、效能、週期性本質三個理由

IoT API感測資料（PM2.5 / 濕度）· mapping 到客戶編號
LINE 對話標籤互動小結 / 分群標籤
▼整合 · mapping（客戶編號 ↔ 設備）
第二層　中台核心 🔒 對內 · 需登入 · 看得到全部資料

運算與產出都發生在這裡

資料整合層客戶編號 ↔ 設備 mapping、生命週期／近三年消費後端加工
分群引擎八分群 sensor_data.py 邏輯（金/銀/銅＋風險軸）
⚙ 報告產出引擎單一引擎，兩個出口。對內對外共用，分數只算一次
內部 Dashboard 三層① 總覽（全會員趨勢）② 分群分析 ③ 個人詳細（Salesforce＋IoT＋LINE＋AI建議）
▼產出「當下」的個人／設備報告，寫入快照
第三層　快照牆 🧱 內外邊界

Report Snapshot（安全邊界）

中台把每台設備的報告存成快照，配一個不可猜的專屬 token。對外層只讀這裡，永遠碰不到內部 DB／API。
快照儲存渲染完成的報告內容（月/季週期）
Token 綁「設備」一台機器一份 → 一位客戶多台＝多連結
可撤銷 / 可設期效長 token 不可枚舉（輕度個資）
歷史歸戶設備過去所有產出報告皆歸戶於該設備 → 累積成每台機器的報告時間軸
▼信件 / QRCode 派送專屬連結
第四層　對外發佈 🌐 對外 · 免登入 · 只讀

客戶端個人報告網頁

客戶收到信或掃 QRCode → 用 token 打開自己那份快照。只揭露金／銀／銅三級 ＋ 行動建議（八分群、AI 服務風險等內部軸不外顯）。
對外出口免登入報告頁 · 揭露：金/銀/銅 ＋ 行動建議
對內出口（同引擎）Dashboard 個人頁 · 揭露：八分群 ＋ AI 建議 ＋ 價值/風險評估
↑ 兩個出口來自第二層同一顆「報告產出引擎」，只差在渲染樣式與揭露深度

三個已拍板的設計決策

1
對外報告採快照，非即時 query。「不預存」原則補一條例外：對外 AirCare 報告一律快照——(a) 公開網頁不直連內部 DB；(b) 上萬份無法每次即時算；(c) 空氣報告本質是週期性月／季報。
2
一套產出引擎，兩個出口，兩種揭露程度。對內 Dashboard 個人頁與對外客戶報告共用同一顆引擎，分數只算一次，避免兩邊不一致；差別僅在樣式與揭露深度。
3
Token 綁設備而非客戶。一台機器一份報告，token 對應 device；免登入＋輕度個資，token 需長而不可枚舉、可設期效、可撤銷。設備亦為歸戶單位——過去所有產出報告皆歸戶於該設備，累積成每台機器的報告時間軸。
資料源（僅中台可存取） 中台核心（對內·需登入） 報告產出引擎（共用） 快照牆（內外邊界） 對外發佈（免登入·只讀）
9 月底「零版本」落地路徑（先可用再迭代）： 中台批次跑一次 → 產出 100–200 份報告快照 → 靜態託管＋發 token → 檢視報告合理性 → 有問題回 Aircare 討論再出報告 → 報告轉線上報告 → 連結寄信給客戶。 不需即時、不需完整中台上線；三層 Dashboard 於後續階段補齊。
