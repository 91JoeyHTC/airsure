# AIRCARE 報告產製 Dashboard — 系統設計規格

> AirSure 數據中台 C 服務模組。讓業務／CS 一鍵、規模化為每位客戶產出 90 天空氣健康報告,並透過 LINE OA／Email 寄發、回收成效,形成閉環。
> 交付物:互動式 HTML 版面示意 + Word 說明文件(概念+SOP+規格三合一)。

## 1. 概念(給主管)
- 痛點:報告目前人工逐份製作,無法規模化,也看不到整批客戶的進度全貌。
- 價值:規模化產製 / 內外雙報告 / 閉環寄發 / 進度可視。
- 定位:呼應「從家電品牌 → 台灣家庭空氣健康確定性」。報告不是資訊,是身分。

## 2. 資料模型(骨架)
客戶 (1) — (N) 設備 — (1) 報告 — (2) 版本〔內部技術版 AK / 客戶版〕
- 一客戶多設備 → 多份報告書(2 台設備 = 2 份報告)。
- 內部技術版(AK):給內部,保留技術術語,取 AIRCARE 系統輸出。
- 客戶版:給客戶,可截圖分享,套 aircare-report Q1_5 模板。
- 隱私:客戶版用「○家」、只顯示客戶代號、不顯示 MAC、測站寫城市區名。
- 分群揭露:對外只揭露金/銀/銅;風險軸僅內部用(AirCare 分群規則 2026-08-04)。

## 3. 報告狀態機(九態)
1 資料未達標(<90天/無感測) → 2 待補輪廓 → 3 可產製 → 4 內部版已產 → 5 客戶版待審 → 6 已核准 → 7 已寄發 → 8 已開啟/互動 → 9 逾期待更新(>90天,回 3)。

## 4. 清單頁欄位
客戶/代號、輪廓、設備數(可展開)、分群(金銀銅)、資料涵蓋(天/90)、報告狀態(燈號)、待補內容、上次/到期、寄發狀態、操作。KPI:可立即產製 / 本季已寄發 / 待補輪廓 / 逾期待更新。

## 5. 詳細頁結構
客戶基本資料列 → 每台設備一張卡片 → 卡內分頁(內部技術版 AK / 客戶版)→ 寄發面板(核准後啟用)→ 歷史報告。

## 6. 營運 SOP(7 步)
篩可產製 → 補輪廓 → 產內部版 → 產客戶版+預覽 → 核准 → LINE/Email 寄發 → 追蹤 MOT。

## 7. 寄發
- LINE OA(優先,已綁好友):圖文卡+連結,可附掃碼預約。
- Email:連結或 PDF 附件(Playwright 轉檔,沿用 html_to_pdf.py)。
- 前提:狀態須為「已核准」。

## 8. 成效(三個 MOT)
開啟率 / 截圖分享率 / 掃碼預約率。不呈現在報告內,僅後台。100 天 MVP 先看這三個,不急收會員費。

## 9. 功能規格(RD)
- 資料來源:sensor_data.py 分群、設備資料、客戶資料/LINE 綁定、報告資產。
- API:GET /reports/dashboard、GET /reports/{customerId}、POST /reports/{deviceId}/generate?type=internal|customer、POST .../approve、POST .../send?channel=line|email、GET .../metrics、PATCH /customers/{id}/profile。
- 權限:業務/CS(產製寄發)、主管(核准)、管理層(唯讀儀表)。

## 10. 落地
MVP:清單頁+詳細頁+一鍵產客戶版+手動寄發 → 第二階段:接 AK、狀態機自動化、LINE 圖文卡 → 第三階段:MOT 自動回填、逾期提醒、管理層儀表。
下一步:與 RD 確認資料可取用性、定義 MVP 名單、把資料模型與狀態機轉成 DB schema。
