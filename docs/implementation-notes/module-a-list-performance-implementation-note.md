## 重要決策與 pitfall

### 1. 名單母體不是場域清單那份 —— 踩過一次

第一版把母體接 `REPORT_ROWS`（場域清單的 AIRCARE 合格清單），實跑後**名單只有 13 戶、漏斗全是 0**。原因：`ReportDeviceRow.cat` 只有在該設備有設備分析報告時才有值，而目前只有 3 台真實設備有報告檔，其餘 69 位合格客戶的 `cat` 是 `null`。

改為 `FIELDS_A_POP`（1,284 場域），理由有二：

- **語意**：行銷名單是規劃層（要寄報告給誰），母體該是使用中場域；合格清單是執行層（誰現在已經可以產報告），那是場域清單的事。
- **對帳**：族群分析的族群卡也吃 `FIELDS_A_POP`，兩個 tab 的戶數因此可以互相驗算。吃不同母體就會重演「字卡與表各說各話」。

實跑驗證通過：

```
週報 471 戶 = ④濕度風險 415 + ⑤清淨風險 30 + ⑥雙風險 26   ✅
月報  84 戶 = ③銅級 60 + ⑦乾燥 24                          ✅
季報 729 戶 = ①金級 435 + ②銀級 294                        ✅
合計 1,284 = CATEGORY_DIST 總和                             ✅
```

### 2. 寄發頻率由分群推出，不是另外貼的標籤

`CADENCE_OF_CAT`：風險三群（④⑤⑥）→ 週報；銅級／乾燥（③⑦）→ 月報；金銀級（①②）→ 季報。沿用母體生成的既有原則（分群是算出來的，不是貼上去的）。

⚠ 這是**示範規則**。正式版的頻率應由行銷方案設定與客戶訂閱決定，不該由風險度推導 —— 已寫進 plan 項目 3。

### 3. 服務跟進的母體是「點過 CTA 的人」

沒點 CTA 的沒有跟進的由頭，全部放進分母會把轉換率稀釋到失真。卡片副標已標明母體。

### 4. 第二個方案改名

原訂「2026.07 夏季除濕方案」但名單收了 ⑦乾燥群 —— 乾燥要的是加濕不是除濕，名字與名單自相矛盾。改為「**2026.07 濕度改善方案**」，涵蓋過濕與過乾兩端。該方案沒有季報批次（①②③⑤ 不在名單內），卡片顯示 0 戶並灰化，下方給空狀態說明。

### 5. CTA 權重依族群痛點

`CTA_WEIGHT` 讓濕度族群多點「加購除濕」、清淨風險多點「升級機型」。報告內的 CTA 環圈本來就是照客戶痛點排的，平均分配會失真。實跑：週報批次的 CTA 第一名是「加購除濕」51.1%，符合該批以濕度族群為主。

### 6. 成效數字刻意不逐格拆「真實／示範」

場域清單那邊拆是因為那是營運實績。這裡成效事件全是 overlay，真實那 3 戶同樣沒有埋點資料源，逐格拆會讓人誤以為其中一半是實績。改為頁面層標一次母體規模與真實場域數，每張卡標「示範值 · 尚無埋點資料源」。

## 2026-09-08 追加：對齊 Dispatch 資料模型決策

需求方確認了 13 題資料模型議題（記錄於 `docs/dispatch-data-model-spec.md`），其中三項直接改到已上線的畫面：

### 決策 1 —— 目前只有季報這個 report_type

週報／月報確定是**另一種 `report_type`**，但內容與 CTA 尚未定義。原本的畫面把週報 471 戶的完整漏斗、CTA、跟進都算出來，等於把成效掛在一個還不存在的產出物上，是編造。

改法：

- `CADENCE_META` 加 `planned` 旗標，週／月為 `true`
- `ListMember.cadence` 改為 `plannedCadence`（未來預分派），**目前全名單一律走季報**
- 週／月卡改成灰化的「規劃中」樣式：只給預分派規模（471 / 84 戶）與一句說明，**不給任何成效數字**，且不可選
- 季報卡的名單 = 全名單 1,284 戶（不再是 729）

⚠ 週／月報上線時要改回來的兩處，程式碼內已標註：`cadenceSummaries` 的 `planned` 分支、`AListPerformance` 的 `const batch = rows`。

### 決策 3 —— 未達門檻的客戶留在名單內

漏斗第一階與「已寄發」之間插入「**可產製**」，把未達 90 天資料門檻的流失顯示出來。`ListMember.eligible` 為示範假設（約 85% 達標），正式版由中台 `campaign_member.eligible` 回填。

### 決策 8 —— CTA 口徑改為「點擊 ÷ 打開報告」

原本只算「佔所有點擊的比例」（因為沒有曝光分母）。決策 8 定下分母是打開報告數，於是：

- 新增 `ctaInteractionRate()`，卡片標題直接寫「互動率 19.7% = 點擊 115 ÷ 打開報告 585」
- 每個 CTA 多一個 `rateOfOpens`
- 決策 6 定下「報告連結被點開即算已開啟」，漏斗該階副標改為「報告連結被點開」

另補上決策 9／10 的歸因規則到服務跟進卡的註腳：7 天窗、last-click、未點 CTA 直接來電不計入。

### 改後實跑

```
2026.10 噴噴方案 · 名單 1284 戶
  週報 [規劃中] 471 戶(預分派,無成效)   月報 [規劃中] 84 戶   季報 1284 戶
  漏斗 名單 1284 → 可產製 1111(86.5%) → 已寄發 898 → 已送達 875
       → 已開啟 585(45.6%) → 點 CTA 115(9%) → 服務跟進 56(4.4%)
  CTA 互動率 19.7% = 115 ÷ 585
```

預分派仍與族群卡對帳：週報 471 = ④415+⑤30+⑥26、月報 84 = ③60+⑦24 ✅
