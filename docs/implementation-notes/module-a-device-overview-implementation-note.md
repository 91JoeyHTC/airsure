## 關鍵決策

### 為什麼要生成 1,272 筆母體

使用者裁決「篩選全部連動（字卡 + 表）」。原本 `FIELDS_A_FULL` 只有 12 筆，用它餵字卡會讓
「連網設備數 4,832 台」塌成個位數，與同畫面的「1,284 場域」「六大類型 412/386/…」全部打架。

生成器用固定 seed 的 mulberry32，**分布刻意對齊既有 mock，不是隨便灑點**：

| 指標 | 對齊對象 | 實測 |
|---|---|---|
| 場域數 | 1,284 | 1,284 ✓ |
| 六大類型筆數 | `CATEGORY_DIST` | 412 / 386 / 248 / 124 / 78 / 36 ✓ |
| 區域筆數 | `REGION_HEALTH.n` | 8 區全數吻合 ✓ |
| 場域類型筆數 | `SITE_TYPES.n` | 982 / 218 / 64 / 20 ✓ |
| Σ 設備總數 | `TODAY_POWER_ON.total` | 4,832 ✓ |
| Σ 今日開機 | `TODAY_POWER_ON.active` | 4,231（87.6%）✓ |
| 平均 PM2.5 | 既有字卡 2 µg/m³ | 2.00 ✓ |
| 平均濕度 | 既有字卡 58% | 58.4 → 58 ✓ |
| 平均 AirCare 分數 | 既有字卡 82 分 | 81.8 → 82 ✓ |

設備台數用 `popReconcile()` 逐格 ±1 收斂到精確值 —— 靠機率湊近似值會讓「4,832 台」變成
「4,817 台」，同一畫面的兩個數字就對不起來了。

### 真實 vs 示範（AGENTS.md §7 / §10）

- 真實三台的新欄位**一律由報告推導**：`model` ← `meta.model`（空字串標「未登錄」，不補假機型）、
  `humidity` ← `meta.humidityAvg`、`temp` ← `daily[].temp` 平均、`mode` ← 時數占比最高的模式、
  `power` ← `runStates` 正常運轉 vs 關機、`urgentParts` ← `consumables[].urgency`、
  `alarmDevices` ← `meta.lastAlarmCode`
- 生成列一律用「示範客戶 NNNN」與 `C2099` 開頭的編號 —— **不生成像真人的姓名**
- 明細表每列有「真實 / 示範」pill，字卡下方的母體說明列出「其中 N 場域 / M 台為真實設備」

### PM2.5 分級為什麼不是 15 / 35 / 55

真實三台 90 天平均 PM2.5 是 **1.4 / 2.5 / 3.6 µg/m³** —— 室內經過機器過濾後本來就很低。
沿用室外 AQI 的 15/35/55 分級，整份母體會全部落在同一格，篩選等於沒作用。
改用室內實測門檻 **< 2 / 2–5 / 5–10 / ≥ 10**，四格都有量（1018 / 195 / 47 / 24）。

### 時間區間怎麼變動數字

| 母體 | 做法 |
|---|---|
| 真實三台 | 由 `DEVICE_REPORTS.daily` 真算 `slice(-7)` / `slice(-30)` / 全 90 天平均 |
| 示範列 | 區間位移係數 + 以場域 id 為 seed 的決定性抖動（近 7 天波動大、近 90 天最平滑）|

`q`（AirCare 分數）在真實三台**跨區間不變** —— 報告只給 90 天總分，短區間沒有官方計分基準，
不自己編一個。已在 `module-a-overview.ts` 註明。

預設區間是 **近 90 天**，理由是 AirCare 設備分析報告的統計期就是 90 天，
既有檯面數字（2 µg/m³ / 58% / 82 分）也是以此為準；預設 30 天會讓開站數字與過去對不上。

### 連動範圍比需求再多幾張卡

需求只說「字卡 + 表」，但同畫面若只有 KPI 動、分布卡不動，會出現
「目前條件 21 場域」與「全 1,284 場域」兩套數字，看起來像壞掉。因此以下也吃 filtered 母體：

- 六大類型分布（含派工解讀的三個戶數）
- 建議聯繫客戶（三張 upsell 卡戶數 + 標題總戶數）
- 健康度 Top 5、需關注 · 健康度 < 75

**類型流動 · 本月遷移維持靜態** —— 它是每週快照的差分，沒有逐場域的歷史類型可篩；
已在副標註明「全體母體（不受篩選影響）」，避免被當成 bug。

## 順手修掉的問題

| 問題 | 修法 |
|---|---|
| 生成地址出現「南區區光復路」 | 行政區已帶「區/鄉/鎮/市」就不再補；非六都直接寫完整行政區名（礁溪鄉、花蓮市…） |
| 兩筆示範列 `power` 標關機／離線卻有開機台數 | `power` 與 `devOnline` 同源：開機 ⟺ `devOnline > 0`，型別上方註明不變式 |
| 明細表 pager 是假的（寫死 1/2/3/…/143） | 改成真的分頁，每頁 20 列，65 頁，`pageWindow()` 收斂按鈕數 |

## 已知限制

- `AIR_QUALITY_DIST` / `HUMIDITY_DIST`（分類概況 tab）仍是靜態分布，門檻沿用室外 AQI 分級，
  與本輪的室內門檻不一致。屬「分類概況」範圍，本輪未動。
- 生成列的 `nm`（場域名）只有 140 種組合，翻頁會看到重複場域名；地址已加路段後有 971 種。
  真實資料不會有這問題，示範資料為避開門牌號（AGENTS.md §7）保留此限制。
- 「電源」是**場域主要電源狀態**，不是逐台狀態 —— 明細表維持一列一場域（使用者裁決）。
